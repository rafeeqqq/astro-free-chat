In one line: the AI gives a short free reading from the user's own kundli, and a real astrologer gives the upay once they recharge. We test it on a fixed group of lapsed payers against a holdout that gets nothing.

🎯 Problem Overview

Narrative

Free chat is how astrology apps win users back. AT gives every new user a free first chat and uses occasions, like its birthday, to give one to everyone. Astrolokal has no free chat today, because every free minute costs a human astrologer's time, and supply is already short. The closest thing we have is free coins, which cost about 5% of monthly spend (Tejaswi).

Leadership has asked for AI to be used this way. Vandana, 17 Sep: stop investing in AI astrologers as a paid product, and use AI for short hooks in retargeting journeys: idle user → WhatsApp → AI hook based on the last chat → free chat ends in 2 min → transfer to a real astrologer on recharge. Vandana, 18 Sep: "free chat can be leveraged more often to re-convert the user… AI astro can be leveraged heavily here. Check AT, they don't give any insights, only questions and recharge nudge."

Problem statement

Users who have paid before and then go quiet have no low-cost, personal reason to come back. Our WhatsApp win-back messages are generic, and in August they did worse than doing nothing on revenue (ARPU ₹11.25 vs ₹85.38; paying 1.8% vs 5.2%, Hindi/Malayalam/Kannada WATI test).

Hypotheses

  1. A free reading from the user's own kundli and last chat topic gives a lapsed payer a reason to come back that a generic message doesn't.
  2. Holding back the upay for a real astrologer turns that curiosity into a recharge. The AI doesn't have to sell itself, which is where Sitara failed (7% first-to-second conversion once campaign traffic is excluded).
  3. With AI there is no astrologer cost per free chat, so free chat can reach many more users than a human-run version could.

Why now

  • Vandana asked for it as highest priority (18 Sep) and chased the ETA (24 Sep).
  • Every app piece already exists, so no Astrolokal dev time is needed while tech is focused on connectivity fixes for early October.
  • The AI astrologer stack (Omkar wrapper, chart computation, memory summaries) is built and otherwise idle now that Sitara/Omkar are deprioritised as paid products.

How it's built

  • Web chat (Next.js on Vercel, company account, on a company subdomain such as chat.astrolokal.com), built and run by Rafeeq.
  • Chat engine with a single config.yaml that controls everything without code changes:
    • timing
    • persona and header label
    • message length
    • how much the AI reveals
    • scripted opening, hooks and closing
    • topics
    • guardrails
    Every message is logged with the prompt version and a config hash.
  • Opening and closing lines are scripted, not generated: instant and never wrong. The AI only answers what the user types in between.
  • Every AI reply is checked before it's shown.
    • Dropped: dates or timing, remedies, money, mentions of AI, fear, guarantees, filler, and any rashi or dasha that isn't the user's.
    • If nothing passes: one retry, then a safe fallback line.
    • If the model is slow (>6 s) or errors: the fallback line.
  • Safety routes before the AI:
    • distress → Tele-MANAS 14416 helpline, the chat closes, no sales card
    • "are you AI?" → a fixed honest line
    • health questions → "see a doctor"
  • No personal data in URLs. The WATI link carries a random token, and the server maps it to the user.

As a user, I get a short reading that feels personal
  • Replies: max 2 messages, max 12 words each; at most 1 question in the whole chat
  • Only chart facts supplied by the wrapper; no dates, remedies, money, fear or guarantees (enforced by the reply guard)

  • Free time: 120 s, tracked on the server (the user can't extend it by refreshing)
  • At 15 s left: scripted closing lines. At 10 s left: strip changes to the cashback reveal; the hand-off card slides over the chat with the countdown CTA
  • Tapping the CTA opens the deferred deep link into random connect immediately (no waiting for 0)
  • At 0: input locks, the card stays, timer removed. No auto-redirect
  • Card hidden if the chat went through the crisis route
—Auto-opening the app from a timer is blocked by browsers/in-app views, so it's not built
As a user, I can recharge and talk to the astrologer in the app
  • Random connect via existing deep link, with UTM tags utm_source=wati&utm_campaign=ai_free_chat&utm_content={prompt_version}
  • In-session recharge for low balance (existing)
  • 100% cashback on first recharge for pilot users, with a real expiry enforced by the backend
  • V2: details plus free reading auto-sent as the first message
—Cashback budget comes from free coins (Tejaswi)
As the PM, I can change the experience daily and trace every result
  • All knobs in config.yaml; npm run check blocks broken configs; npm test (19 checks) must pass before deploy
  • prompt_version bumped on every change; logged per message with a config hash
  • Read 20 chats per version before judging
—Versions are compared over time against the holdout. No parallel arms on the fixed cohort.

Analytics events (web): link_opened, chat_started, user_message_sent, ai_reply_shown (with flags, fallback, latency), handoff_card_shown, cta_tapped, chat_ended, crisis_routed. Each carries token, prompt_version, config_hash and seconds_left.

Joined from Astrolokal data: app open via deep link, random-connect started, recharge amount and time, talk time, 7-day recharge and 14-day revenue, for both pilot and holdout.

🧪 Experiment or A/B Testing Setup

  • Cohort: about 1,200 lapsed payers: ≥1 recharge, no booking in 14–60 days, birth details on file, app still installed (from MoEngage). Hindi/Hinglish first.
  • Split: random 50/50 when the list is built. Pilot gets the WATI message. Holdout gets nothing. Every pilot user gets the same experience.
  • Size: ~600 per side can detect a move from about 4% to 8% in 7-day recharge. The 4% baseline is an assumption; analytics to confirm, and resize if it's off.
  • Iteration: change one thing per version (hook, reveal level, timing, strip copy), bump the version, and compare versions over time against the holdout.
  • Stop rule: no lift at 2 weeks → change the hook. Still none after 2 versions → stop.

Go-To-Market strategy

  • No public launch. A targeted WATI send to the pilot cohort only.
  • Send in the evening (6–9 pm IST), when consults peak. Stagger over 2 days so the first 100 chats can be read before the rest go out.
  • Astrologers: brief the top random-connect astrologers that some users will arrive from a free AI reading, so the first minute goes on the user's question and not on starting over.
